# Smallest wiring needed for the reviewed D&D gaps

Status: **in progress**, audit only. This answers the owner's 2026-10-11 request to show how far the engine is from using its data, before implementation. The [description review](dnd-description-runtime-review.md) and [record ledger](dnd-description-runtime-coverage.csv) hold the evidence and remaining scope. These are proposed connections, not shipped behavior or executable schema.

The engine has useful foundations: character acquisition and saved choices, attack/save/damage settlement, action budgets, inventory identities, owned conditions, campaign time, and bounded shared steps. The gap is uneven. Several reproduced errors need a connection to an existing hook. Much of the native content needs its parameters moved into data. Some described rules need new reusable operations, and others need world state the game does not yet have. There is no defensible single completion percentage or calendar estimate from the current review.

Code will still implement operations such as rolling dice, applying damage and finding visible targets. The data should choose their numbers, eligibility, timing, choices and costs. A definition using existing operations should work when copied or renamed without registering its identity in loader, UI, resolver or save code.

## Five practical kinds of work

| Gap distance | What is missing | Smallest useful change | Example and priority |
|---|---|---|---|
| Connection fix | The declared value or rule and a consumer already exist, but the normal path does not connect them | Pass the field, call the existing query, or preserve it during actor creation | Lost monster vulnerability; shared Countercharm prompt. **Fix now** because current behavior is wrong. |
| Parameter migration | The behavior works in native code, but its identity or constants select the rule | Author the existing values/predicates in the winning record and read them at the current hook | Ring bonuses, mastery mappings, Flurry count. Ignored authored values: **Fix now**. Stable native policy: **Fix when touched**. |
| Shared operation/event | Several rules require a new reusable behavior, choice, trigger or resource scope | Add the one operation/event the selected real rule needs and reuse the current settlement, controls and budgets | Monster typed riders, Multiattack, optional failed-save replacement. **Fix now** when enabling the affected content; retain explicit partial/unavailable status beforehand. |
| World capability | The engine has no adequate state or interaction for the outcome | Add the smallest observable world model/action, or an explicit human adjudication outcome for inherently open-ended rules | Joint transport, aging, planes and broad Wish. **Fix when touched** for an actual product feature; this prevents full support today. |
| Source repair/promotion | Missing, conflicting, truncated or inactive data cannot supply a reliable executable rule | Select an edition/source, recover missing clauses, then translate to supported operations and promote through the existing loader | Raw/staged records and truncated descriptions. **Fix now before enabling**; do not infer a whole rule from its name. |

These are work types, not five compulsory implementation phases. A complete feature can cross several types. An available spell count is not a measure of distance: 134 of 362 effective spells are available, but 122 use native identity-dependent paths and availability does not certify every clause. Likewise, 212 surviving core-class source features do not mean 212 complete data-driven rules.

## How to use this map

For each future card, follow one actual definition through **winning data → owned grants → offered action/choice → cost → settlement → cleanup/recovery/save**. Document which connection is being added and which clauses stay partial. Prefer one existing operation and one ordinary-path proof over a wholesale interpreter rewrite.

The smallest independent closure examples are preserving supported monster projection fields, connecting shared Countercharm selection, and reading declared item/spell numerical bonuses. A broader but still bounded slice is one monster typed damage rider connected to the ordinary enemy action path. These are options for later implementation, not changes made by this audit or a replacement for roadmap priorities.

This map is a lower bound on the work found so far. The complete monster/spell domains, all core/fixture class and subclass units, all435 core item units and940 root item-reference units have been adjudicated. Remaining root item references, raw/staged alternatives, remaining species references, events/campaigns, loot and194 Markdown companions remain in scope. Pending content is not counted as supported. No gameplay code was changed.
