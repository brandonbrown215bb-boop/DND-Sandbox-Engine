# D&D description-to-runtime review

Status: **in progress**. This extends the [structural first pass](dnd-data-runtime-gap-review.md). The original review is unfinished. Reviewing every catalog file's shape did not establish that its described mechanics were reviewed.

## Coverage and completion standard

The source ledger includes all 276 previously inventoried JSON files, the three staging archives, and 194 Markdown references. Archives were read without extraction; every archived JSON member matches an already inventoried extracted file by SHA-256. Markdown extract renderings, staging notes, status files and readmes remain pending review and comparison with their JSON counterparts where applicable.

JSON harvesting found **11,128 review units**, including 8,082 with descriptive text or copy-modification clauses. These are source occurrences, not distinct rules: exact record content and domain reduce them to 9,584 unique units, of which 7,234 contain text. The extractor retains nested entries, tables, references and choice text. Supplemental `additionalEntries` and `_copy._mod` now also appear in root reporting; this exposes 73 existing units' supplemental/variant clauses without deleting independent child units or changing record fingerprints. Referenced bases still need their own adjudication. It does not infer execution from keywords or declared `rules_status` labels.

Current adjudications cover **3,929 unique content-bound units**, accounting for **4,620 source occurrences**: all nine core species roots, all 37 core species traits, all 36 PHB/XPHB skill references, the complete monster and spell domains including their test fixtures, all 353 core/fixture class units, all 50 core/fixture subclass units, all 435 core item units, and 940 root item-reference units. That leaves **5,149 textual occurrences pending**, plus 1,359 units needing structural review. Root descriptions do not certify their children. Winning source ownership does not prove that a disabled or rejected child feature survives loading.

Each adjudication records the mechanical requirements, current runtime evidence and gaps. It binds to the exact source record, including structured fields; identical prose in different records cannot inherit a support decision. Referenced runtime files also have recorded hashes. Changes to those files or the original source inventory require re-review before regeneration.

Artifacts:

- [Smallest wiring map](dnd-runtime-wiring-map.md): existing hooks, missing connections, dependencies and distance to usable behavior. Audit proposals only; implementation comes later.
- [Coverage ledger](dnd-description-runtime-coverage.csv): source paths, JSON pointers, fingerprints, source ownership and explicit review status.
- [Coverage summary](dnd-description-runtime-coverage.json): file/archive reconciliation and remaining counts by domain.
- [Human adjudications](dnd-data-runtime-adjudications.json): requirements and evidence for reviewed records.
- [Production source ownership](dnd-runtime-source-ownership.json): actual loader registration winners, bound to the registry snapshot and loader/manifest hashes.
- [Coverage generator](../../scripts/audit_dnd_descriptions.py): structural extraction and reconciliation only; it never establishes gameplay support.

Reproduce the ledger with `python scripts/audit_dnd_descriptions.py`. Read the next item-reference batch with `python scripts/audit_dnd_descriptions.py --show items.json --pending-only --unique --limit 40`. Source changes invalidate the first-pass inventory; refresh that inventory and its production registry snapshot before using this command for another revision.

The loader's `_merge_missing_fields` retains fallback `_source`/`_source_record`, even when another definition wins. The effective data are overridden correctly, but these metadata misidentify 371 registry entries. The ownership artifact uses the actual `_registered_sources` table; the CSV's `source` and the description ledger now use that table. `runtime_reported_source_metadata` retains the original metadata for comparison. This correction changes the audit's attribution, not gameplay data or source selection.

The review is complete only when every source occurrence is accounted for as a reviewed unique record, a verified duplicate, a source-only reference with its mechanics assessed, or non-rule metadata. Pending entries, incomplete imports and absent source clauses cannot become supported by default. This is a runtime capability review of the project's actual data; it does not certify unavailable external books.

### Import and root-reference findings

The reviewed root subset includes `/item/0` through `/item/881`, fifty-three independent supplemental subentries (Alchemist, Brewer, Calligrapher, Carpenter, Cartographer, Chariots, Cobbler, Cook, Disguise, Forgery and Glassblower kits), Absorbing Tattoo group `/itemGroup/0`, Dragon Scale Mail groups `/itemGroup/20` and `/itemGroup/21`, and Potion of Resistance groups `/itemGroup/72` and `/itemGroup/73`. Similar names and edition prose stay separate. Awakened/Exalted Blade, Book of Vile Darkness, Charred Wand, Billowing Cloak, Danoth's Visor, Devlin's Staff, Dread Helm and Enchanted Three-Dragon Ante variants were read with their full copy modifications; resolving an unread or incomplete base remains required before promotion. Charred Wand's mixed multi-charge failure outcome is not fully specified locally and needs an explicit selected adjudication.

The newer batch adds concrete distances to usable behavior. Crowbar is a small source/query correction: the winning core definition supplies Athletics +2 for prying, while both reviewed root descriptions require Advantage on Strength checks using leverage. Crystal Balls need actual Scrying support and a remote sensor origin, not a larger local range. Cuddly Mascot consumes its use only when the chosen Fear save succeeds; the payment must occur after settlement. Instant Fortress needs linked room parts, persistent damage and source/siege eligibility; the existing object threshold calculation can be reused. Older Cube of Force needs moving selective barriers, while the newer cube offers charged spell casts instead.

Deck rules were read in full, including all forty-four additional Many More Things entries and both twenty-two-outcome Many Things versions. Most individual grants can reuse ordinary operations after translation. Remaining cards, declared draws, hourly deadlines, replacement draws and deferred choices need a saved deck procedure. The BMT standalone-card collection is a separate assembly/reference payload. A deck's structured `vulnerable` or movement field must not grant a particular drawn card's benefit to every deck owner. Sun, Comet, Donjon, Fool, Knight and Skull materially differ by edition. Soul prisons, property loss and erased events need explicit stored world outcomes; dice and item metadata cannot supply them.

Two additional source/runtime limits are explicit. Deck of Dimensions says the marked teleport is usable within twenty-four hours, but returns the marked card after eight hours; that discrepancy needs a selected ruling. Campfire's immediate Long-Rest benefits cannot simply call the current rest path with `skip_campaign_time`: `Character.long_rest()` still ages Inspiration by eight hours and reverts forms. Separate actual elapsed-time expiration from benefit/recovery settlement for this bounded operation.

The subsequent group clarifies more reusable boundaries. Deck of Oracles can reuse saved roll tokens, but needs ten-minute consultation, eight-hour expiry, sixty-foot range and a Reaction after the roll; the current replacement function substitutes before rolling and reads character features rather than owned items. Demonomicon's older knowledge benefit is double PB, while the newer one is Advantage; its effective ninth-level binding must not change the paid slot. Containment requires ten saved page/creature links, individual seven-day possession cooldowns and actual control transfer. Old highest-CR possession selection differs from the newer eligible-creature selection.

Dimensional Loop needs a temporary adjacency query for a selected distant point, not only teleportation. Shackles prohibit self-teleportation while allowing passage through portals. Sundering Sphere and standalone Donjon Card require linked source/target and target-relative return clocks. Disguise Kit paragraphs about improved social effectiveness supply no fixed numerical benefit; the ledger preserves that limitation. Docent needs an attached assistant's own rolls, perception and chosen spell, rather than giving every listed bonus to its owner. Weather orbs need exact-copy deadlines/suppression plus their actual mile-wide weather, fire or flood transitions. Existing clocks, typed damage and room objects are useful foundations, not full weather support.

Dragon items and dusts make the remaining lifecycle work concrete. Dragonguard needs a Dragon-breath save predicate; Dread Helm's special variant needs a visible Humanoid check target. Dreamlily's benefits exist only while Poisoned by that source, and its one-time zero-HP prevention must retain outright-death handling. Old Dust of Disappearance ends on attacks/casting; new dust also ends after damage, separately per affected creature, with object invisibility retained. Draakhorn starts its Deafened aftermath timer when sounding stops. Driftglobe requires an owned moving light object, grasp termination and blocked-route cleanup.
